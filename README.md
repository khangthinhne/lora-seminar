# LoRA and simulated QLoRA: reproducible toy experiments

CS420 Seminar S08 project. This repository studies LoRA and a simplified QLoRA
composition on small **synthetic** regression problems. It is not an LLM
training project, and no result here should be read as an LLM benchmark.

All measured numbers are labelled **Team experiment (toy, synthetic)**. Method
definitions follow the original papers listed under [Citations](#citations).

## Quick start

Requirements: Python 3.10+, a C/C++ toolchain if PyTorch is not already
available, and GNU Make (Git Bash, MSYS2, Linux, or macOS). CPU is sufficient
for the required experiments.

`make setup` creates `.venv` with `BASE_PYTHON` (default `python`) and installs
the project plus dev dependencies into it. All later targets use that virtual
environment by default. Alternatively, activate your own environment and run
`python -m pip install -e ".[dev]"`.

```bash
make setup       # create .venv and install .[dev]
make test        # pytest
make lint        # ruff check + ruff format --check
make table       # exp01 + D1/D2 tables
make sweep       # exp02, exp03, exp04
make assets      # tables, figures, summary, worked example
make all         # test -> table -> sweep -> assets
```

On Windows with a conda environment whose path contains spaces, pass the
interpreter explicitly:

```powershell
make PYTHON="D:\Program Files\miniconda3\envs\deepfake\python.exe" all
```

`make` exports `PYTHONPATH=src`. If you call a module directly, set it
yourself: `$env:PYTHONPATH="src"` (PowerShell) or `export PYTHONPATH=src`
(bash). Example:

```bash
python -m lora_lab.runner --config configs/exp02_rank_sweep.yaml
python -m analysis.make_tables
```

Expected runtime on a recent CPU: required experiments plus assets take about
7-8 minutes; `make optional` adds about 3 minutes. All runs are seeded, so the
CSV values are deterministic.

## Architecture

```
configs/                  experiment YAML (base.yaml is merged via `extends`)
src/lora_lab/
  registry.py             METHODS, TARGETS, QUANTIZERS, EXPERIMENTS
  config.py               strict YAML validation and deep merge
  data.py                 fixed train/val/test streams from a seed
  train.py                generic Adam + MSE loop
  metrics.py              pure metric functions
  memory.py               analytical parameter/storage estimates
  records.py              fixed CSV schema
  runner.py               CLI, provenance, config copy
  methods/                full_ft, lora (AdaptedLayer subclasses)
  targets/                low_rank, decaying_spectrum
  quant/                  identity, absmax_block
  experiments/            exp01 ... exp07
analysis/                 tables, figures, summary (CSV-only)
tests/                    contract, LoRA math, quantization, records, determinism
report/                   summary, worked example, diagram
```

Every adaptation method implements `AdaptedLayer` (`forward`,
`effective_delta`, `merge`, `from_base`). The training loop, metrics,
experiments, tables, and figures use only that interface and the registries.

## How to add a new method

1. Read the method's original paper; do not implement from memory.
2. Create `src/lora_lab/methods/<name>.py`, inherit from `AdaptedLayer`, and
   decorate the class with `@register(METHODS, "<name>")`.
3. Import it in `src/lora_lab/methods/__init__.py`.
4. Run `pytest tests/test_method_contract.py`. The contract test is
   parameterized over the registry, so the new method is tested automatically.
5. Add one block to `configs/exp02_rank_sweep.yaml`, for example:
   ```yaml
   methods:
     - {name: lora, grid: {r: [1, 2, 4, 8, 16], alpha: [16]}}
     - {name: <name>, grid: {...}}
   ```
6. Run `make sweep && make assets`; tables and figures update without changes
   to `runner.py`, `train.py`, `metrics.py`, or `analysis/`.

The same pattern applies to targets (`TARGETS`), quantizers (`QUANTIZERS`),
and experiments (`EXPERIMENTS`). During development we verified this workflow
with a temporary one-file stub method, ran the contract test, and removed it.

## Data and methodology

- Base weights `W0`, inputs `X ~ N(0, I)`, and targets are synthetic.
- `low_rank` target: `W* = W0 + delta_scale * U V^T`, with rank 8 and small
  observation noise; `decaying_spectrum` controls how much spectral mass lies
  outside a small rank.
- Train/validation/test splits are generated from independent seeded streams;
  the test split is never used for learning-rate selection.
- Hyperparameters live in YAML (`configs/base.yaml` and per-experiment files),
  never in Python.
- Learning rates are selected on validation MSE and reported on test MSE.
- Memory numbers are analytical estimates that exclude activations. They are
  not measured GPU allocations.
- Simulated QLoRA uses simple absolute-max block 4-bit quantization. It is
  **not NF4** and is not a faithful reproduction of the QLoRA paper's kernel.

## Results at a glance

See `report/results_summary.md` for the generated tables and limitations.
Highlights from the recorded toy runs:

- In `exp02`, full fine-tuning reached test MSE `6.154e-06 +/- 2.689e-06`;
  LoRA `r=8` reached `3.439e-06 +/- 2.146e-07`. LoRA slightly outperformed
  full fine-tuning here, which is an optimization/regularization effect in this
  toy problem, not a general claim.
- Ranks below the target rank underfit (`r=1`: `2.058e-01`), while `r=8` and
  `r=16` approached the full fine-tuning error.
- In `exp03`, full fine-tuning beat LoRA at `gamma=0.5`; LoRA `r=16` beat full
  fine-tuning at `gamma=2`. The measured ordering is reported without forcing
  it to match intuition.
- The merge check passed: worst absolute difference was `5.245e-06`, below the
  `1e-05` threshold.
- Simulated 4-bit quantization increased LoRA `r=8` test MSE from
  `3.439e-06` to `9.321e-03`; this measures sensitivity in the toy setup only.

## Limitations

- Synthetic data, synthetic base weights, and toy scale (`d = k = 256` for the
  main experiments; `d = k = 1024` only for the D1/D2 parameter table).
- CPU toy timings are not representative of GPU or LLM training.
- Analytical memory includes weights, gradients, and two Adam moments, but
  excludes activations and allocator overhead.
- The simulated QLoRA path uses absmax block quantization, not NF4, and no
  paged optimizer or double quantization.
- Conclusions are conditional on the chosen target, optimizer, and
  hyperparameter grid; they do not generalize to LLMs.
- `exp07` was not run, so no DistilBERT/SST-2 numbers are reported.
