5. Trainable parameter count ≠ GPU memory. Never use these two concepts interchangeably in a table or caption.
6. When experimental results are small-scale/synthetic, use cautious language ("in this setup", "suggests that"). Do not use "proves".

## 3. Extensible architecture (read carefully)

Principle: **everything that may change is a plugin registered through a registry**, and the runner works only with interfaces; it does not know specific method names.

Four independent extension axes:

| Axis | Registry | Current examples | New additions (examples) |
|---|---|---|---|
| Method (adaptation approach) | `METHODS` | `full_ft`, `lora` | bottleneck adapter, IA³, DoRA… |
| Target (ΔW* to be learned) | `TARGETS` | `low_rank`, `decaying_spectrum` | `sparse`, `block_diag` |
| Quantizer (base W handling) | `QUANTIZERS` | `none`, `absmax_block4` | other quantizers |
| Experiment | `EXPERIMENTS` | `param_table`, `rank_sweep`, … | new experiments |

QLoRA **is not a separate class**: it is a composition of `quantizer=absmax_block4` + `method=lora`. This is how to add a "QLoRA-like" approach without duplicating code.

### 3.1 Method interface (mandatory contract)

```python
# src/lora_lab/methods/base.py
class AdaptedLayer(nn.Module, ABC):
    """A frozen base weight W0 (d x k) plus a method-specific trainable part.

    Shapes: W0 is (d, k); forward maps (..., k) -> (..., d).
    """

    @abstractmethod
    def forward(self, x: Tensor) -> Tensor: ...

    @abstractmethod
    def effective_delta(self) -> Tensor:
        """Dense (d, k) update currently represented: W_eff - W0. Used by generic metrics."""

    @abstractmethod
    def merge(self) -> nn.Linear:
        """Return a plain nn.Linear equivalent (inference form, no extra latency)."""

    def trainable_param_count(self) -> int:
        return sum(p.numel() for p in self.parameters() if p.requires_grad)

    @classmethod
    @abstractmethod
    def from_base(cls, w0: Tensor, **hparams) -> "AdaptedLayer": ...
```

Registration:

```python
# src/lora_lab/registry.py
METHODS: dict[str, type[AdaptedLayer]] = {}

def register(registry: dict, name: str):
    def deco(cls):
        if name in registry:
            raise ValueError(f"duplicate registration: {name}")
        registry[name] = cls
        return cls
    return deco

# usage
@register(METHODS, "lora")
class LoRALinear(AdaptedLayer): ...
```

Because metrics use `effective_delta()` and `trainable_param_count()`, **every new method automatically works with all experiments, metrics, tables, and figures** without modifying the runner.

### 3.2 Target, quantizer, and experiment interfaces

```python
class Target(ABC):
    @abstractmethod
    def make_delta(self, d: int, k: int, rng: torch.Generator, **cfg) -> Tensor: ...
    # returns ΔW* (d, k), already scaled per cfg

class Quantizer(ABC):
    @abstractmethod
    def quantize(self, w: Tensor) -> "QuantizedTensor": ...
    @abstractmethod
    def dequantize(self, q: "QuantizedTensor") -> Tensor: ...
    @abstractmethod
    def storage_bytes(self, q: "QuantizedTensor") -> int: ...   # include scales/metadata

class Experiment(ABC):
    name: ClassVar[str]
    @abstractmethod
    def run(self, cfg: ExperimentConfig) -> list[RunRecord]: ...
```

### 3.3 Dependency rules

- `methods/`, `targets/`, and `quant/` **must not import one another or import `experiments/`**.
- `experiments/` must obtain components only through the registry (`METHODS[name]`), not by importing specific classes.
- `analysis/` must only read CSV files in `results/raw/`; it must **not import `torch` or rerun training**.
- No global variables, singletons, or global `seed_everything`: pass `torch.Generator` explicitly.

## 5. Implementation specifications

### 5.1 LoRALinear

- Parameters: `d, k, r, alpha`. Register `W0` as a **buffer** (or set `requires_grad=False`); it must not be included in the optimizer.
- Initialization: `A ~ Gaussian` (fixed scale, specified in config), **`B = 0`** ⇒ `ΔW = 0` initially, so the model starts exactly equal to the base model.
- `forward(x) = x @ W0.T + (alpha/r) * (x @ A.T) @ B.T`. **Do not** construct a dense `ΔW` in the forward pass (use the rank-r path to save computation).
- `effective_delta() = (alpha/r) * B @ A`.
- `merge()` returns an `nn.Linear` with weight `W0 + effective_delta()`. Add `unmerge` if needed for testing, but it is not required.
- Validate: `r >= 1`, `r <= min(d, k)`; raise `ValueError` with a clear message.
- Docstrings must specify the shape of each tensor.

### 5.2 FullFT baseline

Learn a dense (d×k) `ΔW` directly, initialized to 0, while keeping `W0` frozen. This makes the baseline and LoRA represent the same `W' = W0 + ΔW`, enabling a fair comparison and allowing them to share `effective_delta()`. Note in the docstring that this is equivalent to directly training `W` (same parameter count and same optimization problem).

### 5.3 Data / target

- Default: `d = k = 256` (fast on CPU). The parameter table uses 1024×1024 because it is an analytical calculation and does not require training.
- `W0 ~ N(0, 1/k)`; `ΔW*` is generated by `Target`; `W* = W0 + ΔW*`.
- `low_rank`: `ΔW* = U Vᵀ` with true rank `r* = 8`, plus small Gaussian noise `σ`; normalize so that `‖ΔW*‖_F / ‖W0‖_F = delta_scale` (default 0.5, specified in config).
- `decaying_spectrum`: full-rank ΔW* with decreasing singular values (e.g., `s_i ∝ i^{-γ}`); `γ` is specified in config.
- `X ~ N(0, I)`, `Y = X W*ᵀ` (+ optional observation noise). The **train / val / test** split must be fixed by seed.
- One seed controls: `W0`, `ΔW*`, `X`, and A initialization. Use a separate `torch.Generator` for each task so changing one part does not perturb the others.

### 5.4 Training

- Use one shared loop: `train(layer, data, cfg) -> TrainResult`. Do not use an `if method == "lora"` branch.
- The optimizer must receive only parameters with `requires_grad=True`.
- Default optimizer: Adam; loss: MSE; number of epochs, batch size, and learning rate are specified in config.
- **Fairness across methods**: each method selects its learning rate from the same small grid (`lr_grid` in config) **using the validation set**; report results on the **test set**. Record the selected learning rate. Do not use the test set to select the learning rate.
- Measure `train_time_s` using `time.perf_counter()`; note that timing on a CPU toy experiment is not representative of LLMs.

### 5.5 Metrics (`metrics.py`, pure functions)

- `mse(pred, y)`.
- `relative_delta_error(delta_hat, delta_star) = ‖Δ̂ − Δ*‖_F / ‖Δ*‖_F`.
- `trainable_params(layer)`, `reduction_ratio(full, peft)`.
- Metrics accept tensors and do not know which method produced them.

### 5.6 Simulated quantizer

- `absmax_block4`: split W into blocks (block size is specified in config, default 64), set scale = block absmax, and perform symmetric 4-bit rounding (16 levels). Store indices + scale.
- `storage_bytes` must include the scale. To reference actual NF4, **read the QLoRA paper first**; do not reconstruct the NF4 levels from memory.
- Experiment `exp06`: (a) quantize W0 and measure quantization error; (b) train LoRA on quantized W0 versus (c) LoRA on the original W0, and measure the distance to `W*`. Report both columns; do not claim that QLoRA "fully recovers" the original unless the metrics support that claim.

### 5.7 Memory estimate (`memory.py`)

An analytical function for one layer: weight bytes (according to dtype, quantized or not), gradient bytes (trainable parameters only), and optimizer state (Adam: 2 slots per trainable parameter). Explicitly state that **activations are not included**, which is why parameter count ≠ actual GPU memory. The output is a table; do not measure this on a GPU.

## 6. Experiments

Each experiment is registered using `@register(EXPERIMENTS, "<name>")`, reads configuration from YAML, and returns `list[RunRecord]`. The runner writes the CSV.

### exp01 — Param table (analytical, no training)

Calculate for `1024×1024`: full = `d·k = 1,048,576`; LoRA = `r·(d+k)` with `r ∈ {4, 8, 16}` → `8,192 / 16,384 / 32,768`. Export columns: configuration, parameter count, % relative to full, reduction factor (≈128× / 64× / 32×). Tests must assert these values. Include the estimated memory table (D2).

### exp02 — Rank sweep (main experiment)

`target=low_rank (r*=8)`, `methods = full_ft + lora(r ∈ {1,2,4,8,16})`, plus a "no fine-tuning" baseline (`ΔW=0`). Use 5 seeds. Record: test MSE, rel_delta_err, trainable params, and train time. Expected behavior *to be verified, not forced*: `r < r*` underfits; `r ≥ r*` approaches full FT with far fewer parameters.

### exp03 — Full-rank target

Same as exp02 with `decaying_spectrum`, testing several values of `γ`. The purpose is to show conditions under which LoRA is not optimal (the tail of the spectrum cannot be represented at a small rank). Use this for the section "when LoRA is not suitable".

### exp04 — Merge check

After training, compare `layer(x)` with `layer.merge()(x)` on a test batch. Record `max_abs_err` (expected to be approximately 1e-6 in float32; the threshold is specified in config). The corresponding pytest test must fail if the threshold is exceeded.

### exp05 — α/r scaling (optional)

Compare fixed `α`, `α = r`, and `α = 2r`, both with tuned and untuned learning rates, because α and learning rate interact.

### exp06 — Simulated QLoRA (optional)

See Section 5.6.

### exp07 — peft DistilBERT on SST-2 (optional, requires GPU/Colab)

Only run this after the user confirms GPU availability. Use the `peft` library, `r=4` and `r=16`, and compare accuracy and trainable parameter count. Use the same `RunRecord` schema. Separate these dependencies into extras in `pyproject.toml` (`pip install -e .[hf]`) so the core package remains lightweight to install on CPU.

Run budget: all of exp01–exp04 must finish in under ~10 minutes on a laptop CPU with the default configuration.

## 9. Required tests

1. **Contract test, parameterized over every registered method**: `from_base` runs; output shape is `(..., d)`; `effective_delta` shape is `(d, k)`; `0 < trainable_param_count`; `W0` receives no gradient; `merge()(x) ≈ layer(x)`; default initialization gives `effective_delta == 0` (if the method declares `zero_init = True`).
2. LoRA: `B=0` initially; parameter count = `r(d+k)`; `α/r` scaling is correct; invalid `r` → `ValueError`.
3. Param table: exactly 8,192 / 16,384 / 32,768 and 1,048,576.
4. Quantizer: round-trip error is below the threshold; `storage_bytes` includes the scale.
5. Determinism: same config + seed → same result (strict tolerance).
6. Records: writing and then reading the CSV preserves the schema.

Adding a new method ⇒ the contract test automatically runs for that method; if it fails, the method does not satisfy the contract.

## 10. How to add a new method (checklist)

1. Read the method's original source (paper). **Do not implement from memory.**
2. Create `src/lora_lab/methods/<name>.py`, inherit from `AdaptedLayer`, and use `@register(METHODS, "<name>")`.
3. Import the module in `methods/__init__.py` (or use auto-discovery if available).
4. Run `pytest tests/test_method_contract.py`. Fix issues until all tests pass.
5. Add a block to `configs/exp02_rank_sweep.yaml`, for example:
   ```yaml
   methods:
     - {name: lora, grid: {r: [1, 2, 4, 8, 16], alpha: [16]}}
     - {name: <new_method>, grid: {...}}
   ```
6. Run `make sweep && make assets`. Tables/figures will update automatically.
7. Record AI usage in `docs/ai_usage_log.md` if AI was used, and add a citation for the method source.

It must not be necessary to modify `runner.py`, `train.py`, `metrics.py`, or `analysis/`. If modification is needed, that indicates an incorrect abstraction: fix the abstraction and report it to the user.

Adding a target / quantizer / experiment follows the same process using the corresponding registry.

## 13. Numerical example (`report/worked_example.py`)

Goal: a **correct, complete, step-by-step example**, calculated by a script to avoid manual arithmetic errors. Use small matrices with integers/simple values so readers can verify the calculations by hand:

- `d = k = 4`, `r = 1` (or 2), explicitly specify `α`, and provide `W0` and `x`.
- Print the steps in order: define symbols and dimensions → `W0`, `A`, `B` (with `B = 0` initially) → `ΔW = (α/r)BA = 0` → initial forward pass equals the base model → **one gradient step** with MSE loss on one sample, manually calculate `∂L/∂B`, `∂L/∂A` (note that `A` has zero gradient initially when `B = 0`) → update → new `ΔW` → `W' = W0 + ΔW` → `h = W'x` → verify `h` using `W0 x + (α/r) B (A x)` → compare the parameter counts `d·k` and `r(d+k)` for this example.
- Validate the hand-derived gradients against `torch.autograd` in the same script (assert approximate equality).
- Export `worked_example.md` in Markdown/LaTeX-friendly format for the team to copy into the report.
